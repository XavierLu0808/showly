依据：审查时 `docs/product-promotion-v1.md`、`docs/product-promotion-v1-implementation.md`、实施代码、既有测试及隔离验证。

## 审查结论

**不能确认“已完成约三分之二”，也不能接受“流程、数据、约束、验收严格照做”的结论。当前交付应定性为：产品与活动管理、文字草稿、人工发布记录的部分骨架，尚未达到首版验收。**

原完成报告对卡片、公众号 HTML、MP4 没有产出的承认基本准确，但漏掉了自动采集整条主链，也高估了审核、隔离、任务快照、流程约束与前端可用性。按文件或表数量计算完成比例不能衡量核心用户流程是否可交付，本次不另给缺乏权重依据的百分比。

当前文档明确将“只提供 Web 产品入口，不上传截图和录屏，自动采集并制作宣传包”列为首版验收。三个实施阶段均未完整完成；阶段一也包含演示环境及公开页面自动截图，不能仅将媒体问题归入阶段二。

## 必须优先处理的实现缺陷

以下 P1 表示阻断核心业务或破坏明确约束；P2 表示应在首版验收前修复的一般功能缺陷。

### 1. P1：执行检查后，内容编辑器会遇到运行时类型错误

位置：`easel/promotion/service.py:454`、`service.py:464`；`web/frontend/src/components/promotion/ContentEditorView.tsx:36`。

`get_content()` 将 `reviews.checks` 按原始数据库字符串返回，没有 JSON 解码。前端声明它是 `CheckIssue[]`，直接调用 `issues.filter()` 和 `issues.map()`。

隔离 API 验证：`POST /contents/{id}/check` 返回 200，但 `content.revisions[-1].review.checks` 类型为 `str`，值为 `"[]"`。按前端相同表达式运行 JavaScript，得到 `TypeError: issues.filter is not a function`。即使没有检查问题，也会触发；审核创建的 review 同样受影响。构建成功无法发现这一接口契约错误。

### 2. P1：页面“导出宣传包”链接无法调用导出接口

位置：`web/frontend/src/components/promotion/CampaignDetailView.tsx:125`；`easel/promotion/router.py:362`。

页面使用普通 `<a href>` 发起 GET；后端仅注册 POST。隔离 TestClient 验证：同一地址 GET 返回 **405**，POST 返回 **200**。

后端 ZIP 函数存在，不等于用户能通过已实现页面下载。需统一调用方法并验证实际浏览器下载。

### 3. P1：产品事实更新后，旧审核仍有效；版本确认触发的失效也未持久提交

位置：`easel/promotion/service.py:187`、`service.py:243`、`service.py:249`。

直接 `update_fact()` 修改事实正文、上线状态或确认状态，没有调用审核失效逻辑。隔离验证中，将已上线事实改为计划中后，原内容审核仍为 `approved=true`，`invalidated_at=null`。

另一条路径 `confirm_version()` 在调用 `_invalidate_stale_reviews()` **之前**提交事务，调用之后没有再提交。隔离验证：同一连接读取内容状态为 `ready`，另一连接仍读到 `reviewed`；关闭原连接后，失效修改回滚，状态仍为 `reviewed`。未提交的写事务还可能阻塞其他连接写入。

既有 `test_fact_update_invalidates_reviews` 实际没有修改任何事实，只创建并确认版本，再从同一个连接读状态，因此没有覆盖这两个问题。

### 4. P1：未检查即可审核，跨产品素材和版本能进入另一个产品

位置：`easel/promotion/service.py:538`、`service.py:381`、`service.py:478`、`service.py:745`。

审核接口在当前修订没有检查记录时，直接按空检查列表通过，不会运行规则。隔离验证：正文写“完全免费”且没有定价事实，规则返回 error，但跳过检查调用审核仍得到 `reviewed`。

跨产品引用也仅在可选检查中拦截：B 活动可绑定 A 的版本；B 内容可保存 A 的素材 ID，再跳过检查审核并导出。隔离验证确认 B 的 ZIP 中实际包含 A 的素材文件。

这是本地单人管理多个产品时的归属约束问题，不以开放多人部署为前提。需在写入和导出边界校验归属，并使审核依赖当前修订的有效检查。

### 5. P1：档案确认和方案确认没有成为后端生成前置条件

位置：`easel/promotion/service.py:433`；`easel/promotion/jobs.py:74`；`easel/promotion/generation.py:182`。

内容创建、任务创建和草稿生成均未检查已确认产品版本或 `brief_confirmed`。隔离验证：版本数量为 0、方案确认值为 0，仍成功生成草稿，任务状态为 `succeeded`。

前端默认引导用户先点“确认方案”只是导航顺序，不能证明完成报告所称的后端顺序约束已经实现。

### 6. P1：版本快照和生成输入快照没有实际参与工作流

位置：`easel/promotion/generation.py:53`；`easel/promotion/jobs.py:98`；`easel/promotion/service.py:498`。

`build_context()` 始终读取产品实时事实，没有使用活动 `version_id` 指向的事实快照。隔离验证：v1 快照仍是“批量处理”，绑定 v1 的活动上下文已读成后来改写的“能力已撤回”。

任务默认保存 `params={}`，修订 `input_snapshot` 从未由生成流程写入，仍为 `{}`。重试无法重现原产品事实、素材选择和活动配置。画像、品牌红线、语气等字段也未完整进入实际生成提示词；不能以数据库里存在字段作为已完成上下文绑定的依据。

### 7. P2：重复确认方案会重复创建内容任务

位置：`easel/promotion/router.py:216`。

确认接口只在单次请求内用 `seen` 去重；虽然读取了 `existing`，但没有使用。隔离验证：同一个角度第一次确认新增 1 条，第二次仍新增 1 条。前端确认按钮没有在已确认后禁用。需按活动、角度、内容形式保证幂等，并定义修改方案后的行为。

### 8. P2：素材引用无法通过空数组解除，生成也未自动绑定素材

位置：`easel/promotion/service.py:492`；`easel/promotion/jobs.py:192`；`web/frontend/src/components/promotion/ContentEditorView.tsx:188`。

保存逻辑使用 `fields.get('asset_refs') or 旧引用`，因此传入 `[]` 会保留原引用；`structure={}` 也无法清空原结构。隔离验证确认清空后仍保留原素材 ID。

生成写入只传标题、正文与结构，不传素材引用；编辑器只展示素材名称，没有素材选择或绑定交互。“产品素材（生成时自动引用）”与实际行为不符，删除保护虽能保护显式引用，却不能保护没有绑定的实际使用素材。

### 9. P2：内容任务未归入活动任务进度，运行中取消无效

位置：`easel/promotion/router.py:281`；`easel/promotion/service.py:372`；`easel/promotion/jobs.py:235`。

内容级任务只存 `content_id`，未填写 `campaign_id`；活动详情按 `campaign_id` 查任务，导致内容生成/检查任务不出现在活动进度中。隔离验证：草稿任务成功后，活动返回 `jobs=[]`。

`cancel_job()` 只更新 queued 状态。隔离验证：running 任务调用取消后仍为 running。前端却对 running 展示取消按钮。重启恢复能把未完成任务标为失败，但不等于步骤恢复、真实运行取消或输入快照已完成。

## 对原完成报告的修正

1. **“12 个对象全部与方案一一对应”不成立。** 当前方案 §2 已包含 15 个对象，且若干字段或关联只有空壳。
2. **“阶段一和阶段三完成度高”需限定。** 阶段一的自动截图和环境配置缺失，阶段三的前端导出有阻断缺陷，文件导入及效果概览未齐。
3. **“六类检查与审核失效全部有测试”不能推出约束成立。** 审核可跳过检查，事实更新路径未测，失效事务没有跨连接验证。
4. **“第 6 节 11 项，可自动化 9 项覆盖”与当前文档不符。** 当前验收表为 **17 项**，自动采集、录制、登录接管、失败步骤、脱敏和媒体降级均缺实现与相应验收证据。
5. `docs/product-promotion-v1-status.md:30` 声称媒体能力检查已完成、`:32` 将 MP4 放到后续版本，与实现及当前方案阶段二不符，应在修复或重新明确范围时同步更正。
6. 原建议先补 HTML、卡片和角度 UI 可以改善演示，但不足以完成现行首版。应同时解决正确性阻断，并规划自动采集主链。

## 实际执行的验证

- 原有测试：`tests/test_promotion.py`，**15 passed in 1.03s**。
- 前端：`npm run build`、`npm run lint` 均通过；构建有大于 500 kB 的包体提示。
- 补充验证：使用临时 SQLite、临时 outputs、独立 FastAPI router + TestClient，强制模板生成以避免依赖外部模型，验证了生成前置条件、接口字段类型、审核绕过、GET/POST 导出差异、确认方案重复、版本事实漂移、跨连接失效回滚、跨产品素材进入 ZIP、清空引用和运行中取消等行为。
- JavaScript 最小复现确认 API 返回字符串会触发 `issues.filter is not a function`。
- 未执行完整浏览器 UI 验收、真实 LLM 输出验收或媒体渲染验收；本次运行证据不能替代这些验收。
- 未修改功能代码、既有需求或原实施状态文档。本文件为独立审查记录。

既有测试通过的原因包括：调用 service 而非点击下载链接；不经过 React；事实失效测试没有修改事实且只使用同一连接；隔离测试只确认可选规则能报错，没有验证写入/审核/导出边界；导出测试接受 reviewed 或 exported，未强制验证导出状态记录。

## 建议整改与验收顺序

1. 修复检查返回类型、下载调用方法、事实失效事务、强制检查、跨产品归属、快照与生成前置条件，补对应回归验证。
2. 走通“公开产品入口 → 解析并确认档案 → 确认采集方案 → 真实截图入库 → 截图卡片与公众号 HTML 下载”的最小成品闭环；绑定版本和素材引用。
3. 完成受控演示环境、真实操作录制、步骤断言、脱敏、登录接管/恢复及 MP4 合成；验证失败步骤不能被当成成功结果。
4. 补角度/自定义方向、活动配置与简报编辑、AI 局部修改、官方发布入口、日历、文件导入和效果比较建议。
5. 按当前 17 项验收表逐项列出测试或人工验证证据。在公开与需登录演示站点完成不上传素材的整轮验收后，再报告“首版完成”。
