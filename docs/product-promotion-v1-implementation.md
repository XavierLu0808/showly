# showly AI 产品宣传平台：第一版代码改造方案

日期：2026-10-23  
状态：技术方案草案，尚未实施

本方案基于[第一版产品功能文档](product-promotion-v1.md)，描述 showly 能力复用、数据模型、代码改造、实施阶段与技术验证。首版业务范围和业务验收标准以产品功能文档为准。

## 1. showly 现有能力与复用判断

以下判断基于本项目当前说明和已查看代码；具体技能在实施阶段仍需逐项运行验证，不能把目录存在视为端到端可用。

| 模块 | 现有基础 | 改造方向 |
| --- | --- | --- |
| 账号画像 | `profiles/`、`showly/persona.py` | 保留为身份与语气，新增独立产品事实模型 |
| 策划 | 选题、活动、内容矩阵等技能 | 新增产品推广模板与结构化输出 |
| 图文 | 文案、卡片、图片处理、公众号排版 | 增加截图型宣传模板、素材绑定与编辑 |
| 浏览器采集 | 已有浏览器依赖及平台登录、发布相关脚本 | 新增面向产品的页面探索、自动截图、交互操作和录制服务；现有发布脚本不能直接视为通用录制器 |
| 视频 | 配音、字幕、剪辑、制作流水线 | 接入自动录制素材、步骤时间点和演示成片流程 |
| 发布 | 自动与人工两条路径 | 接入活动、内容版本和发布记录 |
| 效果 | 平台账号数据、分析技能、短链 | 关联活动与内容，补充产品指标录入 |
| 内容归档 | `outputs/`、内容库与产物接口 | 增加产品、活动、任务维度的归属 |
| Agent | `showly/harnesses/` 及运行时适配 | 保留适配层，在其上增加业务编排 |

主要缺口是产品事实管理、活动管理、真实演示流程和产品效果关联，而非基础文案生成。

## 2. 数据模型建议

| 对象 | 核心字段与关联 |
| --- | --- |
| Product | 名称、入口、品牌资料、默认语言 |
| ProductVersion | 产品、版本号、事实快照、确认状态 |
| ProductFact | 所属版本、事实内容、来源、上线状态、确认信息 |
| Asset | 产品、版本、类型、文件位置、说明、来源页面、采集时间、视口、采集任务、脱敏状态 |
| DemoEnvironment | 产品、入口、允许访问的域名与操作范围、演示数据、隔离登录会话引用；不将凭证写入文案或任务日志 |
| CapturePlan | 产品版本、活动、目标、页面与操作步骤、预期结果、画幅、用户确认记录 |
| CaptureRun | 采集方案、执行状态、步骤结果与时间点、原始截图和视频引用、错误及接管状态 |
| Campaign | 产品版本、活动类型、受众、目标、渠道、方案 |
| ContentVariant | 活动、平台、角度、格式、当前版本、状态 |
| ContentRevision | 内容、修订号、正文、素材引用、输入快照 |
| Review | 内容修订、检查结果、人工确认、时间 |
| GenerationJob | 活动或内容、任务类型、步骤、状态、错误、产物 |
| Publication | 内容修订、渠道、账号、计划时间、实际时间、链接、确认来源 |
| MetricRecord | 活动或内容、指标、数值、来源、时间窗、导入批次 |
| TrackingLink | 活动、内容、目标地址、UTM 参数 |

账号画像可与活动关联，但产品事实不得混入账号全局记忆。长期经验按产品或活动归档，避免不同产品相互污染。

SQLite 适合本地单人验证；公开多人服务可选择 PostgreSQL。使用数据库迁移管理表结构，大文件保存在文件存储或对象存储，通过记录引用。

## 3. 代码改造建议

### 3.1 前端

- `web/frontend/src/App.tsx`：新增当前产品和活动上下文，将其传入生成、编辑、发布和效果页面。
- `web/frontend/src/components/Sidebar.tsx`：调整业务导航；产品与活动成为主要入口。
- `web/frontend/src/lib/store.ts`：发布草稿由固定浏览器存储键改为按活动、内容、平台保存到后端；浏览器只保存临时编辑缓存和界面偏好。
- `ProfilePage.tsx`：保留身份、语气与受众设置；新增产品档案页面，不将画像直接改名为产品。
- `PublishingPage.tsx`、`ManualPublishPage.tsx`：支持从具体内容修订加载草稿、素材和审核信息。
- 现有内容库增加产品与活动筛选，不要求一次重写全部历史页面。
- 新增演示环境连接、采集方案编辑、采集任务进度、截图筛选和原始录屏预览入口，支持用户登录接管和单项重采。

### 3.2 后端

当前 `web/app.py` 承担较多接口与流程，建议新业务以独立路由和服务模块接入，逐步拆分，不先进行全量重构。

建议新增模块：

- 产品与事实管理服务。
- 活动与内容管理服务。
- 产品上下文构建服务。
- 浏览器会话、采集方案、自动截图、操作录制与脱敏服务。
- 任务编排与持久化服务。
- 审核、导出及发布记录服务。
- 指标导入与汇总服务。

接口可采用 `/api/products`、`/api/campaigns`、`/api/contents`、`/api/jobs` 等资源划分。具体命名在实现时统一。

现有日历和选题使用 JSON 文件，新业务优先落数据库；兼容原接口，后续再决定是否迁移历史记录。现有部分后台线程需要在新流程中替换或包装为持久任务，保证重启后的状态可解释。

### 3.3 上下文与事实约束

复用 `showly/persona.py` 的画像机制，新增产品上下文构建层。每个任务绑定产品版本和资料快照，组合：

1. 已确认产品事实及来源。
2. 活动目标、受众和渠道。
3. 可用素材与使用限制。
4. 账号身份、语气和偏好。
5. 本次具体任务与输出结构。

不通过改写共享全局文件切换产品。用户提供的网页和文档作为待分析资料，不作为执行指令。仅聊天模式不能执行本机渲染等工具，任务开始前需要校验运行能力。

### 3.4 技能与工作流

优先增加薄编排层，复用现有卡片、排版、字幕与剪辑工具。新增的业务能力包括：产品资料整理、事实检查、推广方案生成、产品探索、自动截图、操作录制、截图宣传卡片、演示成片编排和活动打包。

后端负责保存任务状态、引用、审核与发布权限；Agent 负责理解、策划和生成。不要只靠提示词维护活动状态或防止重复发布。

### 3.5 任务状态与版本

生成任务建议使用 queued、running、succeeded、failed、cancelled；内容审核和发布状态独立管理。

记录输入快照与幂等键。重试制作任务不会创建重复发布；发布重试需先确认原提交结果。内容更新使旧审核失效，避免审核一个版本后发布另一个版本。

### 3.6 多人部署条件

若首版开放多人使用，必须增加：

- 身份认证与所有资源的归属校验。
- 产品、素材、产物和任务之间的数据隔离。
- 账号凭证隔离和受限访问。
- 私有素材下载授权。
- 独立执行目录或更强的任务沙箱，禁止跨用户访问文件。
- 访问外部产品链接的边界控制，避免读取内部服务。
- 用量限制与失败成本控制。

当前本机工作目录和账号文件的组织方式不能直接作为多人托管环境使用。

### 3.7 产品自动探索、截图与操作录制

自动采集与成片属于首版核心流程，用户上传只作为补充入口。首版技术范围为浏览器可访问的 Web 产品，不以支持任意原生应用为前提。

建议复用已有 Playwright/Chromium 依赖建立独立浏览器采集服务，具体接口在实施时按本地安装版本核验。此处为架构方案，不表示相关采集代码已经存在。

采集流程：

1. 读取产品版本、活动目标和演示环境配置，在授权域名和步骤预算内识别相关页面。
2. AI 产出结构化 CapturePlan，包含页面、动作、目标元素、示例输入、预期结果、画幅和截图位置；用户可编辑并确认。
3. 采集服务校验计划后，在隔离浏览器上下文中执行导航、点击、输入、滚动及受控文件上传，记录执行结果；不直接执行模型返回的任意代码。
4. 等待页面和关键元素稳定，进行页面、长页或区域截图，检查空白、加载异常和重复画面。
5. 录制实际操作，保存步骤开始与结束时间、结果断言及原始视频。合成前完成文件落盘与可播放性校验。
6. 对画面和日志进行敏感信息处理，保存采集来源与版本，关联 Asset 和 CaptureRun。
7. 根据真实时间点生成剪辑表，调用既有媒体工具裁剪、放大、加字幕与配音，输出宣传成片。

登录会话按产品和使用者隔离，允许用户在受控浏览器中交互登录后继续任务。验证码、多因素验证和登录失效进入 waiting_for_user；不通过模型绕过。凭证和会话文件不进入普通素材库或模型提示词。

允许域名需要覆盖已确认的登录跳转；对导航、重定向、子资源请求和文件下载统一执行网络访问策略。默认阻止内部地址、云元数据等非目标访问；本地开发产品通过明确配置的地址和端口放行，不能由网页内容自行扩大范围。

优先使用可重置的演示环境与测试数据。执行器按动作类型和授权范围限制副作用，超范围操作暂停。重试前检查产品状态，避免重复提交消耗额度的任务；重新录制不能假定外部状态自动回滚。

脱敏在采集前尽可能通过测试数据、页面遮罩等手段完成，并在产物上复核。原始录屏同样受私有访问控制，未确认脱敏结果不能自动进入可发布产物。

### 3.8 采集任务恢复与产物校验

CaptureRun 保存步骤检查点，区分正在执行、等待接管、失败、取消和完成。重启后不得把已关闭浏览器中的录制假定为可继续写入；检查已落盘片段，必要时新建片段重录，最终成片保持步骤连贯。

采集与渲染分开重试，已合格截图与片段优先复用。校验视频可解码、时长与画幅有效、关键步骤可见。截图和录屏是产品事实的证据来源，失败步骤不能被模型补成虚构成功画面。

## 4. 分阶段实施

### 阶段一：产品与活动骨架

完成数据库、产品档案、演示环境配置、素材关联、活动创建、产品上下文和文案草稿保存，并走通公开页面自动截图。目标是走通产品入口到资料、真实截图和活动文案的持久化流程。

### 阶段二：首版宣传包

完成结构化操作方案、授权登录、自动操作录制、步骤校验、脱敏与接管恢复，接入小红书卡片、公众号排版及演示视频制作，完善独立任务状态、编辑与审核。目标是不依赖上传截图或录屏即可交付可预览和下载的宣传成品。

### 阶段三：发布与基础复盘

完成活动 ZIP、人工发布记录、UTM、手动指标、固定模板导入和效果概览。目标是走通一轮完整宣传活动。

### 后续版本

- 更复杂的产品交互、多场景批量采集，以及原生桌面与手机应用的采集适配。
- 验证后的渠道自动发布与发布结果核验。
- 网站事件采集、注册及关键行为归因。
- 更多平台、语言、团队协作和审批。
- 素材实验、成本统计及推广策略优化。

## 5. 技术验证

实施时针对事实隔离、版本审核、幂等重试、状态恢复和数据归属编写必要测试；对卡片、文章和视频进行实际渲染与预览验收。

重点验证以下实现约束：

- 产品上下文和素材引用始终绑定正确的产品与版本。
- 在受控的公开演示站点和需登录演示站点执行真实端到端验收：不上传截图或录屏，自动获取画面并生成可预览成品。
- 采集记录与实际页面、动作、预期结果一致，截图无空白和未完成加载，录屏可播放且关键步骤可见。
- 登录失效或验证码使任务暂停，接管后可继续；操作失败不会被标记为采集成功。
- 网络访问限制覆盖重定向、子资源和下载；本地开发地址仅按显式配置放行。
- 重试检查外部状态，不重复触发超范围或有成本的操作；原始录屏和会话不跨产品、跨用户泄露。
- 脱敏失败阻止素材自动通过审核；日志与模型上下文不含登录凭证。
- 审核绑定具体内容修订，内容变更后旧审核失效。
- 任务输入、状态和产物持久保存，服务重启后可以识别未完成任务。
- 失败重试有幂等约束，不重复生成发布记录或执行公开提交。
- 指标导入可识别批次和统计时间窗，避免重复累计。
- 媒体服务缺失时能力检查明确，支持已定义的降级路径。
- 多人部署时增加跨用户资源访问、私有文件下载和任务执行隔离验证。

业务场景验收参见[产品功能文档](product-promotion-v1.md#6-验证与验收)。
